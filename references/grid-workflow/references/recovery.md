# 中断、延迟与历史问题

出现异常先检索本机既有项目维修手册/SOP；本机没有手册时说明缺失，再以当前证据定位。历史案例只提供假设，不能证明本期状态或扩大权限。

| 症状 | 首要检查 | 恢复边界 |
| --- | --- | --- |
| 汇总缺数 | 隐藏/筛选行、真实末行、分页、表头错位、少了来源sheet | 只重读缺失范围；完整来源再汇总 |
| 数量对但等级错 | 是否误用了建议/关联输出等级 | 追溯业务调整等级列，逐ID比较 |
| ID变日期序号 | 原始单元格类型和显示值 | 授权后还原月-日；保留原值 |
| 多sheet级别不同 | 每个sheet真实等级和行号 | 输出冲突，不自动择一 |
| 写后列表0或少 | 回执、分页、计数读模型与实际成员 | 有限只读复查，不重复保存 |
| 黑名单校验过但缺失 | 是否只做only_check、是否正式提交、是否审批中 | 按差异续接，不整批重传 |
| 状态数量不符 | 开启/关闭/审批中、历史关闭残留 | 比开启集合，分开新增/恢复/关闭 |
| 浏览器句柄失效 | 当前控制连接与标签是否存在 | 只恢复一次；先重新枚举绑定、只读验证，再写 |
| 飞书null没清旧说明 | 原格是否被跳过 | 回读，合法更新说明；真清空按授权执行 |

提交状态未知、登录/权限错误、schema缺失、非目标字段变化、来源变更、数量/集合验收失败时停止相关写入。网络瞬时失败有限重试（通常最多两次），写入须先确定前次未提交；不能用循环重跑替代诊断。

恢复先保留已验收阶段和原提交日志。等级已完成、黑名单失败，只续黑名单；黑名单已受理、审批未完，只查询审批后状态；截图错误只换图，不重跑配置。旧脚本`--skip-active`若伪造回读结果，不可作为四档完成证据。

历史脚本含个人范围、表格链接、业务数量、状态默认值和重试逻辑，仅供取证。新一轮不执行“最新修改文件”推断；先核对周期、来源指纹、目标池、计划和确认范围。包内离线脚本不会调用这些旧脚本。

故障恢复后复验原失败样例和成员集合、非目标对象、格式/截图，再更新本地维修案例与项目交接。离线测试通过、配置通过与真实业务效果分别报告。
