# 中断、延迟与历史问题

出现异常先检索本机既有项目维修手册/SOP；本机没有手册时说明缺失，再以当前证据定位。历史案例只提供假设，不能证明本期状态或扩大权限。

| 症状 | 首要检查 | 恢复边界 |
| --- | --- | --- |
| 汇总缺数 | 隐藏/筛选行、真实末行、分页、表头错位、少了来源sheet | 只重读缺失范围；完整来源再汇总 |
| 数量对但等级错 | 是否误用了建议/关联输出等级 | 追溯业务调整等级列，逐ID比较 |
| ID变日期序号 | 原始单元格类型和显示值 | 授权后还原月-日；保留原值 |
| 多sheet级别不同 | 每个sheet真实等级和行号 | 输出冲突，不自动择一 |
| 写后列表0或少 | 回执、分页、计数读模型与实际成员 | 有限只读复查，不重复保存 |
| 黑名单校验过但缺失 | 是否只做only_check、是否正式提交、是否审批中 | 按差异续接，不整批重传 |
| 状态数量不符 | 开启/关闭/审批中、历史关闭残留 | 比开启集合，分开新增/恢复/关闭 |
| 浏览器句柄失效 | 当前控制连接与标签是否存在 | 只恢复一次；先重新枚举绑定、只读验证，再写 |
| 飞书null没清旧说明 | 原格是否被跳过 | 回读，合法更新说明；真清空按授权执行 |

提交状态未知、登录/权限错误、schema缺失、非目标字段变化、来源变更、数量/集合验收失败时停止相关写入。网络瞬时失败有限重试（通常最多两次），写入须先确定前次未提交；不能用循环重跑替代诊断。

## 请求、分页和检查点

配置读取要求 HTTP 成功、至少一个 `code/status` 且所有已返回业务码均为0，再检查本接口的必需 `data/list/total`。`90000/invalid connection` 是读取异常，不能因为登录探针接受过该码就返回空对象继续删配。`total:null`、空字符串、缺失不能转换成0；真实 `0`、`false` 也不能被默认值覆盖。

按当前返回的实际每页条数计算分页，不能用请求的 `page_size` 推断已读全。总量、记录ID、网格ID分别闭合，空缺页、重复页、未知状态均停止。分页中总量改变标为 `READ_SNAPSHOT_CHANGED`，丢弃该轮不稳定集合，不判保存失败、不重复上传。

只读瞬时故障保留已完成页检查点；续读须核对本期来源指纹、垂类、任务池、总数、首页内容及页码结构。首尾/总数未变不证明中间记录绝对未变：存在并发编辑或状态持续变化时重读稳定快照，保留各垂类实际采集时间。不把旧检查点当作本次最新结果。

## 已受理写入的只读恢复

- 删除/保存每批先持久化请求对象、源指纹、目标URL和开始时间，再发一次写请求；持久化失败不得发出请求。响应原文及接收时间也需落证据。
- 续接先区分未发出、结果未知、已受理待回读、已核验。只有所有原写请求有可验证受理回执、每个非零等级唯一保存一次且源/任务池一致，才进入只读恢复；未知结果、缺档或重复先单独审计。重新执行带 `--apply/--resume` 的旧文件不天然安全。
- 列表可能从0逐批增长；只读预算按本次实测和接口时延设置并记录，不能把固定轮数或某次观察间隔当作后台TTL。达到上限标“已受理、待同步”，保留日志、停止后续写入，诊断当前URL、原回执和schema。取得新读取证据后可以再核验，不能无限重跑原流程。
- 只对已确认的分页变动或同步延迟重读；权限、残缺结构、真实等级错配、非目标字段变化立即停止。正确总数出现后仍逐ID/等级和字典验收。

可用 `scripts/runtime-guards.mjs` 的 `collectPages/assertReadOnlyResume/waitForReadback` 建立这些边界，详见 [接口](runtime-guards.md)。辅助函数不自动接管历史脚本，不把检查点里的声明当作真实回执。

恢复先保留已验收阶段和原提交日志。等级已完成、黑名单失败，只续黑名单；黑名单已受理、审批未完，只查询审批后状态；截图错误只换图，不重跑配置。旧脚本`--skip-active`若伪造回读结果，不可作为四档完成证据。

历史脚本含个人范围、表格链接、业务数量、状态默认值和重试逻辑，仅供取证。新一轮不执行“最新修改文件”推断；先核对周期、来源指纹、目标池、计划和确认范围。包内离线脚本不会调用这些旧脚本。

故障恢复后复验原失败样例和成员集合、非目标对象、格式/截图，再更新本地维修案例与项目交接。离线测试通过、配置通过与真实业务效果分别报告。
