# 黑名单口径与状态

## 两种口径，写前明确

1. **不清理来源**：只用本期确认的不清理等级网格，可来自单独的完整黑名单汇总。不能假定普通汇总已含所有不清理网格。
2. **全量反向匹配**：每个垂类本期全量网格集合`U`，本期四档并集`A`，目标黑名单`B=U-A`。`A`必须包含在`U`内；不在全量表的有效等级ID是来源不一致，先处理，不能静默丢掉。

不得由历史月份决定本次口径，不把全量总行数等同唯一网格数。完整读取CSV/表格所有行、隐藏行及分页，按垂类+ID去重；全量快照的月份/生成时间与本次计划对应，空缺不使用旧文件兜底。二手、线下池、其他任务有不同适用范围时分开。

## 新版页面

进入黑名单列表，定位目标垂类，点“查看”，再点“服务网格”。新版通常用“批量添加”上传，原SOP的“覆盖上传”不是当前默认做法。上传单列Excel表头按当前模板核对，历史为`服务网格ID`。

全量读出该垂类服务网格记录，核对分页稳定、记录ID唯一及真实总数。已验证的旧状态编码为`0=开启、1=关闭、2=审批中`，但本次必须与页面标签/schema交叉验证；未知编码停止判断。

按网格集合分类：

| 目标和当前状态 | 处置 |
| --- | --- |
| B中且开启 | 已生效，保持 |
| B中且不存在 | 待新增，展示来源 |
| B中且关闭 | 待恢复，独立列出 |
| B中且审批中 | 等待审批，不重复添加 |
| 不在B中但开启 | 待关闭，尤其A与黑名单交集 |
| 不在B中且审批中 | 不直接操作，核对审批对象及撤销能力 |
| 不在B中且关闭 | 历史记录，不算有效黑名单，不必删除 |

待补传和待关闭是两类写入。用户只确认“关闭”时不顺手新增；用户只确认“上传”时不擅自关闭。

## 校验、提交和生效

- `only_check=true`只校验不正式新增；确认当前页面是否两次确认，不凭按钮名猜。
- 用ID集合核对可新增/恢复、已存在/跳过、无效集合互斥且覆盖上传批次，不能只比较相加数量。skip可能包含关闭或审批状态，不能一律当已开启。
- 不能仅看`HTTP 200`、`status=0`、`code=0`其中一个证明成功，必须检查本接口实际响应契约；关键字段缺失视为未知，不用undefined当成功。
- 当前业务配置（如新建限制项）保留原值或按本次需求明确设置；不能把历史`create_goods_limit_cfg=2`当固定规则。
- 提交成功只表示请求受理。审批中单列，用户说审批完成后再读状态；没有明确授权不发起/代办审批。
- 页面总量异步更新不能触发重复上传。提交意图和回执先持久化；查询完整状态集合后判断缺失/待恢复/关闭，不把校验通过但没正式提交的网格标为完成。

最终目标是**开启集合等于本期有效目标B**，且`开启黑名单∩有效四档集合`为空。历史关闭记录不应计入生效量，审批中不能算完成。数量相等但成员不同、类型/任务池错误都不通过。实际分发停止效果如需验证，须另看业务打标/分发证据，配置状态不替代业务效果。

## 无效网格

记录网格ID、垂类、原等级、来源sheet/行、后端原因和跳过时点；在用户指定汇总备注列注明。不改业务等级、不删除源行。当前批次可新增/skip/无效的逐ID闭合后，按已确认无效处置继续。

历史接口线索：`sh-elanceattradmin/black/detail/query`、`detail/batchAdd`、`detail/operate`。关闭操作用当前记录ID，不能拿网格ID替代记录ID。接口/状态不明时回页面核对，禁止用only_check、上传或保存来猜测当前配置。
