# 任务规则矩阵

本文件是路由表，不是永久的当前配置快照。每次执行仍需读取最新后台和飞书数据。

## 核心商品/新建品补渠道

- 处理等级/优先级：按当次需求和现有任务定位，不凭名称猜。
- 核心商品：商品 ID 聚合列按周度替换/追加。
- T-90 新建品：历史配置可能从商品 ID 改为日期、商品渠道数量、网格优先级和销量排序；以最新需求为准。
- 站外渠道：集合 `113545`（行业新品站外渠道）和 `113548`（核心商品&新建品站外渠道）必须显式配置。
- 常见保留：垂类、店铺抓取标；未要求变更的条件、排序、处理人和顺序保留。
- 后续新建品补渠道可能要求“新品关键词扫描=是”并移除 P0/P1，不能套用旧版本。
- 开混排垂类必须同步混排引用。

## 新品在售率

- 处理等级：`【新品在售率】-商品ID高优`。
- 优先级：`具体到商品id`；服装历史上可能有专业性和非专业性两个优先级。
- 商品 ID：读取飞书 `在售项目-关联组-已录入未关联属性明细` 最新 revision、按垂类最新日期批次取 ID；历史 ID 默认保留。
- 渠道数：当前要求为 `商品渠道数量 < 3`，不是 `商品SKU平均渠道数 < 3`。
- 排序：`按商品ID升序`。
- 用户明确排除新品在售专项的垂类不新增；未明确时先确认。
- 负责垂类中没有最新批次时，不删除历史 ID，也不主动创建空优先级。

## 渠道在线率供给需求

- 目标垂类和任务池必须从需求确认。
- 集合 `113576`：数码、电器历史专项，复制历史优先级并显式替换集合条件。
- 集合 `113179`：P0 网格在线率唯品会专项；优先级命名通常为“垂类+渠道在线率供给需求-集合id：113179”。
- 只做渠道属性关联池时，不补线下商品池或其他任务池。
- 服装专业性/非专业性可能使用 `113719` / `113652`，并通过网格 ID 区分。
- 某垂类无同名历史任务时不得猜复制来源。

## 无供给店铺渠道补充

- 任务池按需求填写，可能是线下商品池渠道/属性维度和属性关联池。
- 店铺 ID 从飞书聚合列读取。
- 常见条件：店铺抓取标、垂类、渠道销量 `>100`、分发黑名单。
- “是否现有品牌=是”只有需求明确时才配置；用户曾明确要求不配置时不能加回。
- 特定垂类是否加店铺抓取标按专项确认。

## 商品全周清

- 任务包：`【商品全】-周清`。
- 常见条件：对应抓取店铺、渠道检查任务 ID、对应商城；是否现有品牌字段只有后台存在且当次明确要求时才加。
- 7 月已配置保留，8/9 月按最新标签模板新增或调整。
- 飞瓜/抖音按用户要求合并为一条商城逻辑。
- 用户明确排除的垂类或商城不配置；没有当次确认不能套用历史例外。
- 商城/任务标识必须读取后台真实选项，不能只按名称猜。

## 95 分高价值渠道

- 处理等级：限制处理等级 1-4 中各配置一条，名称 `95分高价值渠道`。
- 关联侧：商城 `95分 APP`、店铺抓取标、垂类、分发黑名单=否。
- `渠道价值分=高价值` 仅新建侧配置，关联侧不添加。
- 涉及垂类按需求确认；只执行当前用户明确负责且未排除的垂类。
- 已开混排的垂类，普通处理等级与混排处理等级的映射必须逐条核对；未开混排时不新建混排。

## 待补渠道标签任务

- 常见条件：垂类、一级类目、店铺抓取标、待补渠道商品标签、渠道 SKU 曝光 UV、商品 SKU 曝光 UV。
- 排序通常为待补渠道商品 SKU UV 降序。
- 已开混排垂类必须加入混排；处理等级顺序和混排顺序分开验证。

## 发展部趋势品渠道补充

- 集合 `112715` 必须显式写入。
- 常见保留：垂类、一级类目、店铺抓取标和需求指定排序。
- 特定垂类店铺抓取标是否配置需按当次需求确认。

## 核心网格在线率专项

- 关联侧常见任务池：渠道属性（配色）关联池。
- 集合 `113719`；服装非专业性单独用 `113652`，专业性仍用 `113719`，并用网格 ID 区分。
- 优先级名称、处理等级名称、渠道集合条件分别验收；名称看起来正确不能代替集合字段。
- 历史任务可能位于“渠道在线率供给需求”而不是同名处理等级，先按集合 ID 搜索真实位置。

## 数码行业新品渠道收录

- 仅配置当次确认的四项条件：商品 ID、数码抓取店铺、数码垂类、分发黑名单=否。
- 商品 ID 从当次指定文档聚合列读取，不复用旧快照。
- 优先级通常放在混排 1 商品全下面；新增后检查混排引用。

## 不操作网格高产出渠道收录

- 处理等级：`不操作网格高产出渠道收录`。
- 优先级：`115851`。
- 集合 `115851` 必须是筛选条件，不由名称推断。
- 黑名单按需求为“全部”。
- 店铺/垂类抓取标按需求配置；任何垂类都不能套用其他用户的历史例外。
- 优先级放置处理等级 1 之前，具体顺序写前确认。

## 抖音 Top 商品/有佣渠道任务

- 处理等级/优先级名称按当次需求。
- 商城为抖音；商品 ID 使用文档聚合列。
- 渠道集合、店铺/垂类抓取标、黑名单和优先级位置分别核对。
- 不从“抖音”自动推断渠道集合或商品 ID 来源。

## 有效上线率专项

- 处理等级：`有效上线率专项待关联渠道`。
- 属性关联池优先级历史为 `120452`，后续如需求要求更新为 `121863`，只保留最新集合并回读确认。
- 集合 ID、店铺/垂类抓取标、黑名单=否分别验收。
- 位置通常在线率与核心商品补渠道之后，具体按当前后台顺序核对。

## 全局分发黑名单

- 目标是普通优先级的 `is_black` 条件，不等同于服务网格黑名单。
- 统计空值、未配置和非“否”三类，先排除用户明确不配置的垂类，再按用户确认范围写入。
- 写后按垂类、处理等级、优先级逐项回读。
- 不把历史部分成功数量当作当前最终结果。
