# 失败防复发

## 已发生问题

- 渠道集合 ID 只写在优先级名称里，实际 `channel_id` 没有配置；根因是脚本只写了店铺/垂类/黑名单，回读也没有断言集合字段。
- 复制对象时重建空条件对象，导致原有条件、排序或处理人丢失。
- `商品渠道数量` 与 `商品 SKU 平均渠道数` 字段混用，导致鞋类、数码、电器、母婴进入错误口径。
- 新优先级保存成功但没有加入混排，原因是后台保存接口与混排接口独立。
- 截图登记写到相似但错误的 sheet。
- 使用历史数量或旧商品 ID，未按最新飞书 revision 和日期批次读取。
- 处理人临时改成指定兼职人后直接恢复成固定用户，而不是依据修改前快照恢复原处理人。
- 后台脚本 profile 路径混淆，刷新了上级 profile，实际 `level_config_rpa/.browser-profile` 仍未登录。

## 强制断言

写前：

- 目标垂类、任务池、处理等级、优先级和来源明确。
- 每个需求条件都有字段映射。
- 渠道集合 ID 已列入计划，不仅出现在名称中。
- 非目标字段快照已保存。
- 混排状态和登记位置已确认。

写后：

- 目标字段值、操作符、展示名称和三处存储一致。
- 商品 ID 无重复，最新批次无缺失，历史 ID 未被误删。
- 非目标条件、排序、处理人、等级顺序和其他优先级未变化。
- 混排引用、顺序和登记单元格已回读。

任一关键断言失败，停止后续批量写入并生成失败结果，不得报告“配置完成”。
