# 等级1至4的后台配置

## 确认稿

包含本期来源/读取时点、负责与排除垂类、任务token和任务池、网格维度、四档源数量/有效数量/无效数量、要删除的旧分配范围、黑名单模式及差异、线下池是否包含、登记位置。源缺等级/冲突、后台映射不唯一、权限失败时停止对应写入。

“删除所有处理等级再建1至4”在网格任务中指删除已确认范围内的旧**网格分配记录**，不删除策略等级定义、优先级、处理人、混排或其他任务池。含糊时先问清，不把历史全量授权带到本月。

## 写前

- 打开真实网格分配页，逐垂类核对页面和ID；记录URL、任务和池标识。
- 读取该范围所有旧分配记录，完整分页；验证总量、唯一记录ID及网格ID。零值不能靠`value || oldValue`兜底。
- 读真实等级字典及ID。后台“限制型处理等级1”等别名须按当前字典确认；不默认所有垂类都有相同名称或ID。
- 每个候选网格校验存在、垂类和状态；无效记录带原因及证据。用户明确允许跳过时剔除并备注，未授权先展示明细。
- 原配置/等级字典/黑名单完整快照、来源指纹和计划落本地证据目录；确认方案所有新网格/等级可提交后再删除。

## 执行

1. 写前再读目标范围确认无并发变更。按明确的记录ID删除旧网格分配，限定垂类、任务token和任务池；不按页面全选跨范围删除。
2. 保存删除回执。读取延迟时继续只读核查，不因暂未归零重复删。
3. 依次保存等级1至4，每档使用本期校验通过的ID集合和已核实等级ID；零数量档保持为空，不塞占位ID。
4. 每批记录意图、提交开始时间、返回及回读，结果不明先查原请求/页面，不直接重发。中断仅续接未完成批次。
5. 全部目标垂类1至4完成后再处理黑名单，若用户另定顺序则按本次要求。

## 验收

按`垂类+任务池+等级+网格`核对成员集合，分别计算漏配、多配、等级错配和重复；数量相同但ID不同也失败。核对所有四档及真实总量，独立与源业务等级比对。不从生成expected的同一份错误映射自证正确。

列表/计数有异步延迟。记录提交回执，有限只读轮询；超时报告“已提交、页面待同步”，不说配置失败或盲目重建。最终重新读取真实成员，不以出现一次正确数量代替集合核验。需要续接黑名单时必须有本期当前四档回读证据，不能用虚构`afterSave`或旧快照替代。

确认非目标垂类、其他任务池、等级定义、优先级条件、处理人和混排未变。二手的线上与线下池是两个独立目标，只有明确要求“两边”才同时执行；分别留证据，不能由一边成功推断另一边完成。

## 历史接口定位线索

曾验证的网格服务路径位于`sh-griddistributeadmin/distribute`下的`cfgList`、`cfgList/dealLevelList`、`gridCheck`、`cfgDel`、`saveOrEditCfg`。这些不是允许绕过页面和权限的通用API承诺，先核对当前schema、任务池字段及可信适配器，不在公用包拼接SSO认证。
