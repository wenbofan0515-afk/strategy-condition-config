# 任务池范围与启用状态

## 目标对象

任务池范围来自本次后台完整读取的 `verticals[].task_pools`。Skill 不维护固定任务池白名单，避免新任务池出现时被静默漏检。

每个任务池至少包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `task_pool_id` | 后台任务池唯一 ID |
| `task_pool_name` | 后台当前展示名称 |
| `task_pool_type` | 后台任务池分类，能读取时优先使用 |
| `status` | `active` 或 `inactive` |
| `complete` | 该任务池详情和分页是否完整读取 |
| `levels` | 处理等级1至4的完整结果 |

## 排除规则

按以下优先级判断店铺收录任务池：

1. `task_pool_type` 等于后台已核实的 `store_collection` 或其他明确的店铺收录类型。
2. 类型缺失时，`task_pool_name` 去除首尾空白后完整等于 `店铺收录`。

仅出现“店铺”或“收录”字样不能触发排除。名称为“合作店铺下渠道收录”“商品渠道收录”或其他渠道收录类型的任务池继续校验。

排除结果必须保留在报告的 `excluded_task_pools` 中，包含任务池 ID、名称、类型和排除原因。

## 启用状态

- `active` 任务池进入网格集合校验和跨任务池一致性校验。
- `inactive` 任务池只进入启用状态矩阵，不参与等级映射比较。
- 垂类没有任何 active 任务池时，输出 `not_applicable`，记录未启用任务池列表和读取证据。
- active 任务池的 `complete` 不为 `true` 时，输出 `pending` 或 `unknown`，不能用空 levels 代替完整读取。
- active 任务池缺少处理等级1至4中的任何一个等级对象时，视为读取不完整。零网格等级必须用存在且完整的空集合表达。

## 跨任务池规则

每个垂类先按以下对应关系归并，一类任务池只占一行。保留原任务池 ID、名称和启用证据供明细追溯。

| 归并后任务池 | 一级类目＋品牌 | 二级类目＋品牌 |
| --- | --- | --- |
| 商品关联任务 | 商品关联任务 | 商品关联任务-服务网格 |
| 线下商品池 | 线下商品池(新)（配置页别名：渠道维度线下商品池） | 线下商品池-服务网格 |

有一个版本启用时展示该版本及粒度。两版本均未启用时合记一行。均无启用证据且有状态不明确时合记待核验。若两个版本均有启用证据，汇总标为版本冲突，两个版本的读回证据均保留。

同一垂类下，使用服务网格的 active 任务池按 `grid_id -> level` 核对。一级类目＋品牌保留等级计数，只有取得确认的服务网格映射后才能逐格判断。校验时：

- 先按源表构造期望映射
- 再逐池比较源表和可比的实际映射
- 最后比较使用服务网格的 active 任务池之间的实际映射

任务池未启用属于范围状态，不代表等级配置通过。任务池已启用但没有完整映射时，必须列入待处理差异。

## 本期垂类范围

`verticals` 是当期纳入校验的垂类白名单。源表、等级配置、黑名单、汇总和明细统一使用它。若当期不做图书、其他，就从该期白名单排除。后续周期使用该周期确认的垂类。店铺收录仍按任务池正式分类独立排除。
